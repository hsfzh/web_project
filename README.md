# 감정의 흔적

## 작품 질문

우리가 하는 말들은 AI에게 어떤 흔적을 남길까?

## 작품 소개

사용자가 입력한 문장을 감정으로 해석하고, 감정의 이름과 비중, 색을 움직이는 빛으로 표현하는 인터랙티브 웹 작업이다. 말의 의미를 설명문으로 돌려주는 대신, 문장이 화면에 남긴 감정의 흔적을 빛의 색과 움직임으로 보여주는 것을 목표로 한다.

## MVP

GitHub Pages에서 실행되는 웹 페이지이다. 관객은 화면 아래 입력창에 문장을 입력하고 보내기 버튼을 누른다. 분석 결과는 감정 이름, HEX 색상, 비중으로 구성되며 비중에 따라 한 번에 다섯 개의 빛을 만든다. 화면에는 최대 20개의 빛을 유지하고, 한도를 넘으면 가장 오래된 빛 다섯 개를 제거한다.

현재 공개용 코드에서는 API 키가 비어 있을 때 테스트용 무작위 감정을 반환한다. 따라서 이 상태에서는 입력 문장의 내용이 감정 결과에 반영되지 않는다. Gemini API를 연결한 실제 분석은 키가 설정된 경우에만 실행된다.

## 질문과 조사

이 작업에서 살펴보는 것은 AI가 감정을 정확히 판정하는가가 아니라, 문장을 감정의 이름과 색으로 바꾸는 과정에서 어떤 해석이 만들어지는가이다. 같은 문장에도 반가움, 걱정, 차분함처럼 여러 감정이 함께 나타날 수 있고, 감정 이름과 색을 고르는 기준에 따라 결과의 인상이 달라진다.

이를 확인하기 위해 자유로운 문장을 입력받고, AI가 문장에서 감정을 최대 다섯 개까지 추려 각 감정에 이름, 색상, 상대적 비중을 부여하도록 구성했다. 이후 각 감정의 비중을 빛의 개수에 반영하고, 색과 이동 잔상을 통해 결과를 시각화했다. 이는 감정을 객관적으로 측정하는 도구가 아니라, AI의 해석을 관객이 시각적으로 경험하는 작은 실험이다.

## AI 활용 과정 · AI USE NOTE

- Gemini API를 사용해 입력 문장에서 감정 이름, 색상, 비중을 JSON 형식으로 생성하도록 구성했다.
- ChatGPT를 활용해 프롬프트와 응답 검증, JSON 파싱, 빛 생성 로직의 오류를 점검하고 개선했다.
- 감정의 비중을 다섯 개의 빛으로 배분하고, 감정별 색을 빛과 잔상으로 표현하는 방식은 직접 선택하고 조정했다.
- API 키가 없는 상태에서도 화면을 시험할 수 있도록 무작위 감정 생성 함수를 추가했다. 현재 공개용 코드의 빈 API 키는 이 테스트 경로를 실행한다.
- AI가 정한 감정과 색은 입력 문장의 유일하거나 객관적인 정답이 아니다. 프롬프트와 모델 응답에 따라 달라질 수 있다.

## 실패와 배운 점

처음에는 기쁨, 슬픔, 분노처럼 감정을 미리 정해두고 점수만 받도록 했다. 이 방식은 문장에 실제로 드러난 복합적인 감정을 표현하기 어렵다는 한계가 있어, 감정 이름을 자유롭게 생성하는 구조로 바꾸었다. 감정 이름과 색을 모델이 함께 정하게 하면서 문장에 어울리는 결과를 얻을 수 있었지만, 색이 지나치게 옅거나 감정과 잘 맞지 않는 경우도 있었다. 프롬프트에 색 선택 기준을 더 구체적으로 적어야 한다는 점을 배웠다.

또한 AI 응답은 항상 예상한 JSON 구조를 따르지 않을 수 있어 응답을 파싱하고 감정 이름, HEX 색상, 비중을 검증하는 처리가 필요했다. AI의 해석과 화면의 빛 표현을 분리해 두면, 분석 방식이나 시각 효과를 각각 바꾸기 쉽다는 점도 확인했다. 테스트용 무작위 응답은 화면 동작을 확인하는 데 유용하지만, 문장과 감정의 관계를 검증하려면 실제 AI 응답을 사용해야 한다.
